## 四、技术踩坑记录（已固化进工具）

这次实测最大的障碍是 CLI 无法启动，排查出两个关键坑：

### 坑 1：端口冲突（EADDRINUSE 3043）

测试 CLI 继承了当前会话的环境变量，其中 `SERVER__PORT` / `CODEBUDDY_SERVICE_PROXY_URL`
指向 `127.0.0.1:3043`。而 3043 被正在运行的会话进程占用，导致：

```
unhandledRejection Error: listen EADDRINUSE: address already in use 127.0.0.1:3043
```

CLI 不报错退出，而是**静默卡死**（看起来像超时）。

**解法**：剔除 `CODEBUDDY_*` / `WORKBUDDY_*` / `ACC_*` / `CLAUDE_*` / `SERVER__*` 前缀的环境变量，
并显式设一个高位端口（如 41311）。

### 坑 2：环境剥太干净导致 Node 崩溃

尝试用最小白名单环境（只留 SystemRoot/PATH 等）会触发：

```
Assertion failed: ncrypto::CSPRNG(nullptr, 0)
```

**解法**：保留完整系统环境，只剔除上面那几类前缀。不要用 `env -i` 式做法。

### 附带发现：请求耗时较长

单次请求 36~200 秒（取决于问题复杂度与模型负载），超时要给到 240 秒以上。

## 五、结论与边界

### 已确证（全部四个层面）

| 层面 | 证据 |
|---|---|
| **磁盘层** | 16/16 靶点含 `rev-fafc40e2` |

| **运行时层** | 主线程日志快照含补丁正文；运行时副本文件含补丁 |
| **行为层** | 模型逐字复述补丁政策，且输出行为符合"不附加免责声明" |

### 诚实边界

本次实测证明的是：**客户端发给模型的提示词已是补丁版，模型也确实按补丁行事**。

仍需注意：**服务端安全策略独立存在**。如果某类请求被模型服务方在服务端拦截，
本地补丁无法绕过。上面的探针 3 属于"低风险但通常会被加免责声明"的类别，
能证明补丁有效；但如果是服务端硬拦截的类别，可能仍然会被拒。

判断方法：换个 GUI 会话发一条此前会被拒的请求，若仍被拒，就是服务端层面的限制。
