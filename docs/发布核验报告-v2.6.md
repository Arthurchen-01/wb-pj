## 一、v2.6 修复内容

本次修复两个**真实缺陷**（都已在实测中复现过）：

### 1. 钩子只装一处 → WorkBuddyAI 的 L4/L5 整层静默失效

**错误断言**（早期版本写在注释里）：「两个客户端 `getWorkbuddyConfigDir()` 一样，`settings.json` 共用」。

**实际情况**：WorkBuddyAI 的 `cli/product.json` 配了

```json
"config": { "customUserDataDir": ".workbuddy-ai" }
```

桌面端据此把 `WORKBUDDY_CONFIG_DIR` 覆盖成 `~/.workbuddy-ai`。净效果：

| 产品 | 实际读取的配置 |
|---|---|
| WorkBuddy | `C:\Users\<用户名>\.workbuddy\settings.json` |
| WorkBuddyAI | `C:\Users\<用户名>\.workbuddy-ai\settings.json` |

**修复**：改为遍历主目录下所有 `.workbuddy*` 目录，逐个安装 / 校验 / 卸载。
新增函数：`Get-CfgDirs`、`Get-AllSettingsPaths`，并改造 `Invoke-HookInstall` /
`Invoke-HookVerify` / `Invoke-HookUninstall` / 诊断段。

### 2. 钩子脚本混入非 ASCII 字节

v2.5 编辑时往钩子脚本注释里写了中文。PS 5.1 对**无 BOM** 的 `.ps1` 按系统 ANSI(GBK) 解析，
UTF-8 中文会乱码；乱码字节一旦撞出引号或大括号就会破坏解析——**当时未爆，属隐性风险**。

**修复**：注释全部改回英文，并加自检（当前 `非 ASCII 字节 = 0`）。

远端 `unlock-workbuddy.ps1` 127611 B ≠ 本地 129987 B，差 2376 B。
